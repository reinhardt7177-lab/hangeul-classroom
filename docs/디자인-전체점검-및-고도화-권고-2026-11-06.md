## 먼저 개선할 항목

### F01 작은 글자와 주요 버튼의 대비

**P1 · 접근성.** [첫 화면 스타일](D:/국경일계기교육/site/dist/holidays.css:1), [발표 조작부](D:/국경일계기교육/site/dist/presenter.css:24), [한글날 학생 스타일](D:/국경일계기교육/site/dist/tablet.css:1), [개천절 스타일](D:/국경일계기교육/site/dist/gaecheon.css:1)에 걸친 공통 문제다.

Lighthouse에서 첫 화면 로고 아래 11px 설명은 3.32:1, 보조 통계 문구는 3.90:1, 한글날 발표 화면의 흰 글자·주황색 다음 버튼은 검사 크기에서 4.15:1로 나왔다. 학생 화면의 보조 설명과 버튼에서도 3.44–4.11:1 사례가 나왔다. 일반 크기 텍스트의 기준인 4.5:1에 못 미친다.

회색·보조 글자와 강조 버튼의 색을 역할별 토큰으로 정리하고 각각의 실제 배경에서 대비를 검사한다. 모든 글자를 진하게 만드는 대신 본문·설명·비활성·장식의 역할을 구분한다. 그림 위 글자는 실제 배경과 덮개 효과를 함께 검사해야 한다. **권장 작업: `$impeccable colorize`와 `$impeccable harden`.**

### F02 휴대폰에서 작아지는 한글날 발표 본문

**P1 · 반응형과 타이포그래피.** [발표 캔버스](D:/국경일계기교육/site/dist/presenter.css:7)와 [본문 크기](D:/국경일계기교육/site/dist/presenter.css:13)가 원인이다.

3–4학년 첫 발표의 다음 단계인 ‘빈 안내판을 채운다면?’에서 본문은 390px 화면에서 6.732px, 320px 화면에서 5.472px로 계산됐다. 같은 장면이 1024px에서는 18px로 표시된다. 고정 16:9 캔버스와 `1.8cqw` 글자 크기가 함께 축소되기 때문이다. 휴대폰에서 화면은 깨지지 않아도 실제로 읽기는 어렵다.

전자칠판의 16:9 구성은 유지하되 좁은 화면에는 별도 읽기 배치를 제공한다. 글자 크기 하한만 올리면 현재의 절대 위치 배치 안에서 겹칠 수 있으므로 본문·그림·선택지의 재배치가 함께 필요하다. 발표를 휴대폰에서 지원하지 않을 방침이라면 학생용 화면으로 연결하는 명확한 안내가 대안이다. **권장 작업: `$impeccable adapt`와 `$impeccable typeset`.**

### F03 학생 글자 선택 버튼을 가리는 고정 링크

**P1 · 조작과 반응형.** [한글날의 고정 국경일 링크](D:/국경일계기교육/site/dist/hangeul.html:13)가 원인이다.

390×844의 학생용 글자 탐험에서 ‘국경일 모아 보기’가 화면 아래에 고정돼 모음 ‘ㅏ’와 ‘ㅓ’ 버튼 일부를 덮었다. 링크 영역은 x=18, y=682, 너비 약 113, 높이 32px였고, 두 버튼과 실제 교차 영역이 생겼다. 해당 링크는 발표 모드에서만 숨기며 학생 모드에서는 남아 있다.

학생 화면의 상단 탐색 또는 일반 문서 흐름 안으로 이동한다. 단순히 다른 고정 높이로 옮기면 스크롤에 따라 다른 버튼을 가릴 수 있다. 스크롤 위치·키보드 초점·입력창 표시 상태에서 다시 확인한다. 키보드로 모음을 선택하는 동작 자체는 정상이다. **권장 작업: `$impeccable adapt`와 `$impeccable harden`.**

### F04 끝이 잘리는 교사용 안내 문장

**P1 · 타이포그래피.** [안내문 스타일](D:/국경일계기교육/site/dist/presenter.css:24)과 [안내문 렌더링](D:/국경일계기교육/site/dist/hangeul-presenter.js:108)을 확인한다.

320px 화면에서 ‘함께 나눌 말’ 문장은 표시 폭 306px보다 내용 폭이 357px로 길었다. 한 줄 고정과 말줄임 처리가 적용돼 끝을 볼 수 없고, 이 문장 자체를 펼치는 조작은 없다. 교사 노트는 별도 학습 단위 노트이므로 항상 같은 문장을 보여 주는 대체 경로로 볼 수 없다.

안내문을 두 줄까지 읽을 수 있게 하거나, 키보드로도 여는 ‘안내 전체 보기’를 제공한다. 조작부 높이를 늘리는 경우 발표 캔버스와 다음 버튼이 화면 밖으로 밀리지 않는지 함께 검사한다. **권장 작업: `$impeccable typeset`와 `$impeccable clarify`.**

### F05 화면에 보이는 링크 문구와 접근성 이름 불일치

**P1 · 접근성.** [국경일 선택 링크](D:/국경일계기교육/site/dist/index.html:1)의 두 카드가 Lighthouse의 `label-content-name-mismatch` 검사에서 실패했다.

화면의 동작 문구는 ‘수업 시작’인데 접근성 이름은 ‘개천절 수업 열기’ 또는 ‘한글날 수업 열기’로 대체한다. 보이는 문구를 말해 조작하는 사용자가 같은 이름을 찾기 어렵다. WCAG 2.5.3 관점에서 보이는 핵심 라벨이 접근성 이름에 포함되도록 맞춘다. 제목·실행 문구를 `aria-labelledby`로 연결하고 설명은 별도로 전달하는 방식 등을 검토한 뒤 같은 검사를 다시 실행한다. **권장 작업: `$impeccable harden`.**

## 유지할 요소와 제외한 자동 경고

국경일별 삽화, 밝은 읽기 화면과 어두운 발표 화면, 질문 뒤에 설명을 공개하는 흐름, 무손실 WebP, 현재 학년 두 PDF만 제공하는 자료 창을 유지한다. 글꼴 파일에는 사용하는 400–900 굵기가 실제로 포함돼 있다.

자료 창은 키보드 Enter로 열기, Escape로 닫기, 원래 버튼으로 초점 복귀가 정상이다. 개천절 정답·오답 설명은 클릭과 Space 선택에 반응했고, 한글날 글자 선택도 Space로 조작됐다. 학생 입력란은 검사 화면에서 16px이며, 학생 탭과 글자 버튼에는 충분한 크기의 사례가 있다.

Impeccable 탐지기는 크림색 배경·인용 강조선·색 그림자·영문 보조 제목도 경고했다. 이런 형태 자체를 기능 결함으로 세지 않았다. 기존의 문화·수업 맥락에 맞는 색감을 지우거나 자료 인용 구분선을 없애는 것을 개선 목표로 삼지 않는다. 대비 경고는 Lighthouse의 실제 요소 검사와 교차 확인했다.

## 검수 범위와 근거

Chromium 기반 내장 브라우저에서 1280×720, 1024×768, 390×844, 320×740 화면을 표본 검사했다. 실제 휴대폰의 터치 제스처를 검증한 것은 아니다. 대표 흐름은 국경일 선택 → 학년 선택 → 발표의 다음 단계 → 자료 창 열기와 닫기, 학생 탭 이동과 글자 조합이다. 좁은 화면, 긴 안내문, 고정 링크와 버튼의 겹침을 추가로 검사했다.

| Lighthouse 접근성 표본 | 점수 | 실패한 자동 검사 |
|---|---:|---|
| 국경일 첫 화면 | 94 | 텍스트 대비, 보이는 라벨과 접근성 이름 불일치 |
| 한글날 3–4학년 발표 도입 | 96 | 다음 버튼 대비 |
| 개천절 3–4학년 기록의 성격 | 100 | 표본에서 자동 실패 없음 |

| 개천절 3–4학년 학생 자료 비교 | 95 | 대비 |

100점도 전체 접근성 준수나 모바일 가독성을 보장하지 않는다. 실제 스크린리더, 브라우저 200% 확대, 운영체제 고대비, 모션 감소 설정의 실행 결과, iOS Safari와 실물 전자칠판·학생 기기, 모든 장면의 개별 레이아웃은 이번 검수 범위 밖이다. 모션 감소용 CSS와 기존 음원·모션 자동 검사는 코드 수준에서 확인했다. 타이포그래피 판정은 **Block**이다. F02와 F04처럼 읽기 어려움과 전체 문장을 볼 수 없는 문제가 남아 있기 때문이다.

## 권장 수정 순서

1. `$impeccable harden` · 고정 링크 가림, 접근성 이름, 제목·선택 상태를 먼저 정리한다.
2. `$impeccable adapt`와 `$impeccable typeset` · 발표용 큰 화면을 보존하면서 작은 화면의 별도 읽기 배치와 안내문 전체 보기를 다듬는다.
3. `$impeccable colorize` · 보조 텍스트와 실행 버튼의 대비를 역할별로 교정한다.
4. `$impeccable document`, `$impeccable extract`, `$impeccable layout` · 공통 조작부 규칙을 정리하고 첫 화면 진입과 학생 자료 읽기 순서를 개선한다.
5. `$impeccable polish` · 위 수정 뒤 시각적 마무리를 하고, `$impeccable audit`와 동일 표본 검사로 재평가한다.

위 작업은 하나씩 또는 묶어서 요청할 수 있다. 새 이미지·영상·모션을 추가하기보다 기존 자료가 더 잘 보이고 잘 눌리게 만드는 작업이 우선이다.
